# Guest compatibility: System 7, Mac OS 8, Mac OS 9

Which classic Mac OS releases the AppleBridge guest side runs on, what was measured
on each, and what is expected but unmeasured. The floor and its reasons are
[D-029](../DECISIONS.md); this page is the map above the floor. Every row says how
it is known: **measured** (with a date) or **expected** (an inference, not a result).

and config app use Color QuickDraw ([D-029](../DECISIONS.md)). Below System 7.0 there
is nothing to test — the daemon is built on Apple Events, FSSpec and the Process
Manager, all new in 7.0.

## Mac OS 9 (measured on SheepShaver, 9.0.4)

**What works**, all over the bridge (2026-07-02/03, daemon 0.8d2–0.8d3):

- **The same 68K daemon binary**, unmodified, under OS 9's built-in 68K emulator:
  Open Transport connect, the v0.2 handshake, `mac_status`, screenshots, key
  injection and `mac_menu`. The installer detects Open Transport and writes `NET=OT`.
- **The command tier.** ToolServer and its environment (`Tools:`, `StartupTS`, …) copied
  from an MPW installation and started as an `APP=` helper; `StartupTS` derives `{MPW}`
  from ToolServer's own folder, so the environment is relocatable. Keep it on the
  **local** disk: an `APP=` path on an AppleShare volume fails at boot, before the volume
  is mounted.
- **Native PowerPC builds** with the MPW Golden Master's **MrC + PPCLink**: an MPW tool
  (`-t MPST`, ran and returned its output) and a QuickDraw application (`-t APPL`, PEF
  in the data fork, `cfrg` generated by PPCLink, launched and drew its window).

**What does not, or is not proven:**

- **68K `SC` / `Link` / `Asm` fail silently on OS 9** — status 0, no output, no `.o`.
  SheepShaver emulates the PowerPC and OS 9 emulates the 68K on top of it; the large 68K
  compiler does not survive that (raising its partition 7 → 20 MB changed nothing),
  while small 68K tools such as `DumpFile` run. **Build 68K software on a 68K guest**
  (Basilisk II) and deploy it; on OS 9 use MrC/PPCLink for native code.
- **A CFM/PowerPC application owns its QuickDraw globals**: declare `QDGlobals qd;` at
  file scope, or PPCLink stops at an unresolved `qd` (Error 3034). On 68K the A5 world
  supplies them.
- **`mac_write_file` (`WRITEFILE`) reported success and wrote nothing** on this guest
  (2026-07-03, 0.8d3); writing text through ToolServer (`Echo '…' >> file`) worked. Not
  re-measured with a current daemon.
- **`SWAPSELF` (self-update) is unproven on OS 9.** OS 9 locks a running application's
  file, which `SWAPSELF` avoids by renaming rather than copying; the same File Manager
  call is expected to behave as on System 7, but no on-device test has been run
  ([SELF_UPDATE.md](SELF_UPDATE.md)). Until it is, the first update on an OS 9 guest is a
  Shift-boot (Startup Items off) and a Finder rename.
- **Failures are often silent here**: MrC/PPCLink diagnostics do not come back in the
  Apple Event reply. Redirect with `≥ file.err` and read the file; judge a build by its
  artefact (`Exists`), not its status ([OPERATING_NOTES.md](OPERATING_NOTES.md)).

## Mac OS 8 (not tested)

Nothing on this page about Mac OS 8 is a measurement. What follows is what the releases
imply and what to test first.

- **8.0 and 8.1 still run on a 68040**, ship Open Transport, and run in **Basilisk II**.
  That is single emulation, so the 68K toolchain (SC, Asm, Link/ILink) and the daemon
  build should behave as on 7.6.1. This is the cheap experiment: one more guest row
  ([MULTI_GUEST.md](MULTI_GUEST.md)), the unchanged daemon, the end-to-end smoke test.
- **8.5 and 8.6 are PowerPC-only**; expect the Mac OS 9 situation above (SheepShaver,
  MrC/PPCLink, no 68K compiler).

**Where Mac OS 8 is expected to differ** — risks to measure, not known defects:

- **Sticky menus** (new in 8.0): a click-and-release on the menu bar leaves the menu
  open. An open guest menu starves the daemon (`OTSnd err=-3158`, then a 30 s
  reconnect), so a single `mac_click` on the menu bar may take the bridge down; the
  journaling driver and the real-mouse gestures (`mac_host_menu`) need re-checking.
- **The Appearance Manager** changes window frames, title bars and dialog geometry:
  pixel references (`host/refs/*.json`), the boot shepherd's dialog matching and any
  coordinate-based click would need new references.
- **The multi-threaded Finder** makes copies non-modal, which changes the "a Finder
  modal blocks the daemon" situation the operating notes describe.
- **The Toolbox reference** (`mac_toolbox_lookup`) deliberately carries no Mac OS 8 /
  Appearance material; OS 8-only calls would be written without a lookup.

## What would change this page

- A Mac OS 8.1 guest under Basilisk II passing the smoke test and a menu test written
  for sticky menus.
- An on-device `SWAPSELF` on OS 9, and `WRITEFILE` re-measured there with a current
  daemon.
- A native or fat PowerPC daemon — worth building only if the 68K emulation is shown
  to cost speed or reliability; today it does not.
